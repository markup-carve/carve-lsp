# Development

## Setup and maintenance

```bash
npm install
npm run build
npm test
```

Run the server directly over stdio:

```bash
node dist/server.js --stdio
```

## Diagnostics benchmark

```bash
npm run build
npm run bench:edits
```

`tools/bench-edits.mjs` starts the built server over stdio, opens one
generated document, applies 20 one-character edits 60 ms apart and waits for
the final diagnostics. It does this once with a client that takes pushed
diagnostics and once with one that pulls after every edit, at 2, 8, 32 and
270 KB. The documents are generated by the script, so every run sees the same
input.

Each cell is the user-space instruction count (`perf stat -e instructions:u`)
of the whole server process. Instruction counts barely move with machine load,
so two builds can be compared on a busy machine. About 4 to 4.3 G of each number is
server startup and the initial open, so compare the part above that. `perf`
is required; the script exits with status 2 and says why when it cannot count.

Options: `--sizes 2,8,32,270` (KB), `--modes push,pull`, and `--dist <dir>` to
measure another build on the same input.

## The highlighting grammar

Semantic tokens come from the carve-grammars TextMate grammar, vendored in
`src/carve-grammar.ts` at the commit in `CARVE_GRAMMARS_REV`. To move the pin:

```bash
node tools/sync-grammar.mjs <40-hex carve-grammars commit>
npm run build && npm test
```

The scope-to-token mapping is `tokenTypeOf` in `src/semantic.ts`.
